# Migrating to the recut crate graph and curated facade

This release replaces `rxui`'s five glob re-exports with a curated, layered
public API, deletes two crates, and stops re-exporting the Astrelis engine
wholesale. Every change below is mechanical — a name moved, or a name was
renamed. Nothing changed behaviour.

## Why

The previous split was a `git mv` of one monolith's module list, and the facade
globbed all five crates back into a single namespace, so the boundaries were
invisible to users and unenforced in CI. Three concrete costs:

- **A settings dialog linked wgpu, winit, and a chart renderer.** There were no
  features, so there was nothing to turn off.
- **`pub use astrelis_ui_next as core` was simultaneously too much and too
  little.** It published an entire unpublished crate's unbounded surface from a
  1.0-track facade, and it still did not cover what consumers needed: every
  example and test also depended on `astrelis-core`, `astrelis-paint`,
  `astrelis-platform`, or `astrelis-app` directly, because `LogicalSize`,
  `Color`, `Path`, and every keyboard type live in those crates and
  `astrelis-ui-next` does not re-export them.
- **`rxui-charts` was a 554-line crate whose structural twin already lived in
  `rxui-widgets`.** Its dependency closure was identical.

## Crates

`rxui-charts` and `rxui-controls` are deleted. Four published packages remain,
on one stated axis: **what an application cannot do without, versus what it
can.**

| Was | Is |
|---|---|
| `rxui-charts` | `rxui-widgets`, behind the `charts` feature |
| `rxui-controls` (controls + validation) | `rxui-core` |
| `rxui-widgets` editor/media/inspection data | `rxui-core` |
| `rxui-widgets` node graph, docking, inspector view | `rxui-widgets`, one feature each |

If you depended on `rxui-charts` or `rxui-controls` directly, depend on `rxui`
(with the `charts` feature, if you need charts) or on `rxui-core`.

`rxui-core` now has **no `[features]` table**, and CI asserts both that and that
its dependency closure never reaches wgpu, winit, taffy, arboard, or the
deprecated retained engine.

## Features

`rxui` gained `native`, `native-embedded`, `widgets`, `charts`, `docking`,
`graph`, and `devtools`. `default = ["native", "widgets"]`, so an existing
dependency keeps working unchanged.

`default-features = false` gets the whole component model, including
`ComponentHost`, headless. Measured: 172 crates resolve with defaults, 79
without.

Two honest caveats. Inside this workspace `rxui-core` and `rxui-widgets` have
identical dependency closures, so the widget features buy public API surface and
compile time rather than fewer dependencies; `native` is the only real
dependency cliff. And **"no text shaping" is not a configuration RXUI offers** —
`astrelis-paint` depends on `astrelis-text` and therefore parley
unconditionally.

Features are for *applications*. A library should depend on `rxui-core` directly
rather than on `rxui` with narrowed features, because Cargo unifies features
across a dependency graph: a library that narrows them makes its own surface
depend on whatever its consumer chose.

## The facade

`rxui::*` no longer re-exports everything flat. The root keeps what an
application writes constantly — the `Component` contract, `View`, every container
and control builder, every style token, `Axis`, `Alignment` — and everything else
moved into a module. The hot items are reachable both ways.

| Module | Holds |
|---|---|
| `rxui::view` | The open view protocol, for defining a view kind of your own |
| `rxui::controls` | `radio_group`, `combo_box`, `numeric_field`, `Choice`, `ComboOption` |
| `rxui::forms` | `FormValidation`, `Validation*`, `validated_text_field`, `form_section` |
| `rxui::surfaces` | `dialog`, `toasts`, `toolbar`, `command_palette` and their types |
| `rxui::data` | `property_grid`, `virtual_tree`, `virtual_table` and their row types |
| `rxui::media` | `image`, `render_view`, `ImageSpec`, `RenderViewSpec` |
| `rxui::icons` | `Icon`, `IconSpec`, and the six built-in glyphs |
| `rxui::style` | `Theme`, `ColorRole`, `Space`, and the per-view style builders |
| `rxui::services` | Clipboard, background work, undo history |
| `rxui::inspect` | `InspectionSnapshot`, `InspectionNode`, `ViewStats` |
| `rxui::charts` / `graph` / `docking` / `devtools` / `native` | Optional; each named after the feature that enables it, so a missing item names its own fix |

`rxui::prelude` is now a real prelude — enough to write a component, and nothing
more. It used to be a byte-identical copy of the root glob, which made importing
it tell a reader nothing.

## The engine vocabulary

`rxui::core` is **deleted**. In its place are closed modules that name what they
export, and which together cover what consumers actually needed:

| Module | From | Holds |
|---|---|---|
| `rxui::geometry` | `astrelis-core` | `LogicalSize`, `LogicalPoint`, `LogicalRect`, `Size`, `Point`, `Rect`, `Affine2` |
| `rxui::color` | `astrelis-core` | `Color`, `Rgba8` |
| `rxui::input` | `astrelis-platform` + `astrelis-ui-next` | `UiInput`, every keyboard and pointer type, `CursorIcon` |
| `rxui::semantics` | `astrelis-ui-next` | `SemanticRole`, `SemanticData`, `SemanticNode`, `SemanticAction` |
| `rxui::paint` | `astrelis-paint` | `Path`, `PathVerb`, `Brush`, `Painter`, `Image`, … |
| `rxui::engine` | `astrelis-ui-next` + `astrelis-text` | `UiRoot`, `Element`, `LayoutContext`, `Invalidation`, `NodeId`, the built-in elements, the text vocabulary |

`rxui::engine` is documented **semver-exempt while RXUI is on `0.x`**: it is the
surface a custom `Element` is written against, and that surface belongs to the
Astrelis engine, which is developed alongside RXUI and not yet published.
Everything else `rxui` exports is versioned normally.

`rxui::native` re-exports the eleven-plus foreign types that appear in
`ComponentWindow`'s own signatures, so opening a window no longer requires five
Astrelis crates in your `Cargo.toml`. The engine's `Next*` codenames are aliased
away there: `NextWindowHost` is `WindowHost`, `NextAccessibilityAdapter` is
`AccessibilityAdapter`.

### `rxui::input` constructors

A `KeyboardInput` has eight fields, six of which no caller has an opinion about,
so synthesizing a keystroke meant a fifteen-line struct literal and seven
imports. `rxui::input` provides:

```rust
input::text("a")                       // a keystroke that produces text
input::named_key(NamedKey::Escape)     // a named-key press
input::key(Key::Character("a".into())) // any logical key
input::pointer_moved(point)
input::pointer_pressed(point)
input::pointer_released(point)
input::pointer_wheel(position, delta)
input::with_modifiers(input, modifiers)
```

## Renames

| Was | Is | Why |
|---|---|---|
| `render_surface` | `rxui::media::render_view` | The pair was inverted: this is the real GPU-backed viewport |
| `render_view` | `rxui::data::render_view_placeholder` | This is an inert panel that reserves space and announces a role |
| `DockAxis`, `dock_axis` | `rxui::Axis` | A two-variant shadow of a two-variant enum plus a public converter, buying nothing. `DockNode::Split` now carries `Axis` |
| `NextWindowHost` | `rxui::native::WindowHost` | The `Next` prefix is Astrelis history |
| `NextAccessibilityAdapter` | `rxui::native::AccessibilityAdapter` | Same |
| `NextAccessibilityRequest` | `rxui::native::AccessibilityRequest` | Same |
