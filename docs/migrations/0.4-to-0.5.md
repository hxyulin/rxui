# Migrating from Astreon 0.4 to 0.5

Update every Astreon crate to `0.5`. Existing editor, widget, application, and
native-menu APIs remain source compatible.

Developer tools are intentionally opt-in. Add the `devtools` facade feature and
route `InspectorAction` messages only in development builds. The `testing`
feature now also exposes structural snapshot methods on `UiHarness` plus fixed
font and theme helpers; snapshot strings are plain UTF-8 and do not require a
particular golden-file library.

Astrelis `ElementInspection` gained `kind`, `declared_layout`, `enabled`,
`overflow`, and `z_index`. Code constructing that public structure directly
must initialize the new fields; ordinary callers of `Ui::inspect` need no
changes. Update custom dependency pins to the Astrelis revision recorded in the
Astreon workspace manifest.

CI environments that run the native smoke application need a display server.
Linux uses `xvfb-run`; macOS and Windows runners launch the self-terminating
window directly. Performance enforcement must use a release build.
